1 O modelo relacional
     Segundo Elmasri (2018), o modelo de dados relacional, criado por
Edgar Codd, da IBM Research, em 1970, está baseado no princípio de
que um banco de dados pode ser representado por uma coleção de rela-
ções matemáticas, as quais são representadas de maneira uniforme atra-
vés de tabelas de valores. Esses valores podem ser interpretados como
um fato que descreve uma entidade ou uma instância de relacionamento.

     Uma tabela, ou relação, é composta por colunas e linhas, onde as
colunas são chamadas atributos e às linhas da tabela dá-se o nome de
tuplas. Cada coluna em uma tabela é definida por um domínio que res-
tringe os valores que podem ser armazenados naquela coluna. Como
exemplo, temos a tabela 1 com as seguintes colunas: numat, nome, sexo,
dtnasc e salário. Observe, cada linha da tabela Funcionário é uma tupla.

                                 Tabela 1 – Tabela Funcionário

 121           Edna Martins                 F            21/06/1977       R$ 2.841,71


 345           Pedro Coutinho               M            29/03/1989       R$ 1.460,66




1.1 Atributos, domínios e formato de dado

     Os atributos representam as colunas de uma tabela (Silberschatz, 2020)
e são responsáveis por armazenar as características das entidades repre-
sentadas pelas tuplas. Cada atributo possui um tipo de dados associado,
como inteiro, string ou data, e um domínio para aquele atributo.

    Formalmente, um domínio D é um conjunto de valores atômicos. Por
atômico, entende-se que cada valor do domínio seja indivisível. Alguns
exemplos de domínio são:

    • Idade: é um atributo do tipo inteiro que inclui valores de 0 a 120,
         indicando a faixa etária de uma pessoa.

    • Idade_funcionario: idades possíveis para funcionários de uma
         empresa; cada um deve ser um valor entre 18 e 70 anos.

    • Notas_bimestrais: valores de notas escolares que deve variar de
         0 a 10.

    • CEP: é o código de endereço postal do Brasil formado por 8 dígitos.

    Um formato de dado é também especificado para cada domínio. Por
exemplo, o formato para o domínio CEP pode ser declarado com uma
cadeia de caracteres da forma ddddd-ddd, onde cada d é um dígito.


1.2 Relações e tuplas

    Um esquema de relação R, representado por R(A1, A2, …, An) é formado
pelo nome de uma relação R e uma lista de atributos A1, A2, …, An (Elmasri,
2018). Cada atributo Ai é o nome de um papel desempenhado por algum
domínio D no esquema de relação R. D é dito o domínio de Ai e é repre-
sentado por dom(Ai). Um esquema de relação é usado para descrever
uma relação; R é dito o nome dessa relação. O grau de uma relação é o
número de atributos n de seu esquema de relação. Como exemplo, con-
sidere o seguinte esquema de relação para uma relação de grau 4, que
descreve o funcionário de uma empresa:

    DEPARTAMENTO(nomeDep, numDep, nchefe, dtIniChef)

    Para esse esquema de relação, DEPARTAMENTO é o nome da relação,
que possui quatro atributos: nomeDep, numDep, nchefe e dtIniChef.

1.3 Características de uma relação

    Uma das principais características do modelo relacional é a não orde-
nação das tuplas. No modelo relacional os dados são armazenados em
um conjunto não ordenado de tuplas. Isso significa que não há garantia
de que as tuplas sejam armazenadas em uma ordem específica dentro da
tabela, o que é uma característica derivada da teoria de conjuntos, onde a
ordem dos elementos não é relevante. Além disso, não há duplicação de
tuplas em uma tabela relacional. Cada tupla deve ser única dentro de sua
relação, o que é uma exigência fundamental do modelo (Elmasri, 2018).

    Os atributos de cada tupla são ordenados, ou seja, cada posição de um
atributo dentro da tupla é fixada, e essa ordem é importante para o pro-
cesso de definição e manipulação dos dados. No entanto, cada valor de
atributo deve ser atômico e monovalorado. Por exemplo, o valor de um
campo que representa um nome não pode ser uma lista, mas sim um único
valor, como “João da Silva”. Já a característica de monovalor implica que
cada atributo de uma tupla deve ter apenas um valor por vez, o que signi-
fica que campos como listas não são permitidos dentro da tupla.


1.4 Atributos chave da relação

    Como mencionado anteriormente, uma relação é definida por um con-
junto de tuplas. Assim, todas as tuplas de uma relação devem também
ser distintas. Isto implica que duas tuplas quaisquer não podem possuir

Modelagem relacional                                                    47
a mesma combinação de valores para todos os atributos delas. Ou seja,
os valores dos atributos de uma tupla devem ser tais que possam iden-
tificar a tupla de maneira única.

     Uma superchave (SK) é um conjunto de um ou mais atributos que per-
mitem identificar de forma única uma tupla na relação (Silberschatz,
2020). Isto é, uma superchave é um conjunto, tal que, para quaisquer
duas tuplas t1 e t2, em uma instância r de R, tem-se a restrição que t1[SK]
≠ t2[SK]. Toda relação tem pelo menos uma superchave, que é o con-
junto de todos os atributos (Takai, 2005).

     Contudo, alguns atributos da superchave podem ser redundantes, de
maneira que um conceito mais útil é o conceito de chave. Uma chave é
uma superchave mínima, ou seja, ao remover-se um atributo, perde-se a
unicidade. O termo unicidade indica que nenhum valor da chave pode se
repetir na relação. Cada uma das possíveis chaves de uma relação é
denominada de chave candidata.

     Uma chave primária (do inglês, PK – primary key) é uma chave candi-
data escolhida para identificar de forma única cada tupla da relação. Por
convenção, os atributos da chave primária são sublinhados no esquema
relacional. Exemplo: FUNCIONÁRIO (numat, nome, sexo, dtnasc e salário).
Na relação FUNCIONÁRIO, a chave primária é o “numat” e deve estar sub-
linhada. As outras chaves candidatas são denominadas chaves únicas (do
inglês, UK – Unique Key), e não são sublinhadas (Elmasri, 2018).

     Uma chave estrangeira (do inglês, FK – Foreign Key) é um atributo, ou
conjunto de atributos, em uma relação que faz referência à chave primá-
ria de outra relação. Dessa forma, estabelece-se um relacionamento entre
as tabelas. De maneira formal, um conjunto de atributos FK em um
esquema de relação R1 é uma chave estrangeira de R1 se ele satisfaz
duas regras:

    1. Os atributos de FK possuem o mesmo domínio dos atributos PK
         da chave primária de um esquema de relação R2; os atributos FK
         se referem à relação R2.

    2. Um valor de FK em uma tupla t1 de R1 ocorre ou como um valor de
         PK para alguma tupla de t2 de R2 ou é nulo. No primeiro caso, tem-
         -se t1[FK] = t2[PK], que significa que a tupla t1 se refere à tupla t2.


2 Restrições do modelo relacional
    As restrições do modelo relacional são regras que garantem a con-
sistência e a validade dos dados de um banco de dados relacional. Elas
evitam que informações incorretas sejam inseridas, mantendo a consis-
tência e a integridade do banco de dados. Segundo Elmasri (2018), as
restrições são as seguintes:

    • Restrições de domínio: restrições de domínio especificam que o
         valor de cada atributo A deve ser um valor atômico pertencente ao
         domínio de A.

    • Restrições de valores nulos sobre atributos: outra restrição sobre
         os atributos especifica se valores nulos são permitidos ou não. Por
         exemplo, o nome do funcionário não pode ser nulo, logo, define-se
         uma restrição de valor nulo sobre o atributo nome do FUNCIONÁRIO.

    • Restrição de integridade de entidade: restrição que estabelece
         que nenhum valor de chave primária pode ser nulo. O motivo é que
         uma chave primária é utilizada para identificar uma tupla de maneira
         única na relação, caso existam duas ou mais tuplas com valores
         nulos nas chaves primárias, então não há como diferenciar uma
         tupla de outra.

    • Restrições de chave: a restrição de chave exige que toda relação
         tenha uma chave primária cujos valores sejam únicos e não nulos.



Modelagem relacional                                                               49
       Isto garante que cada tupla seja identificada de forma única na
       relação.

     • Restrição de integridade referencial: é uma restrição utilizada
       para manter a consistência entre duas relações (Takai, 2005). Infor-
       malmente, a restrição de integridade referencial estabelece que
       um valor de atributo que faz referência a uma outra tupla deve se
       referir a uma tupla existente nesta relação. Por exemplo, no banco
       de dados empresa, o atributo ndepto de FUNCIONÁRIO representa
       o número do departamento para o qual cada funcionário trabalha.
       Portanto, o seu valor em toda tupla de FUNCIONÁRIO dever ser
       igual ao valor de numdep de alguma tupla da relação
       DEPARTAMENTO.


3 Mapeamento do DER para o modelo
relacional
     De acordo com Elmasri (2018), as etapas para projetar um esquema
de banco de dados relacional (um projeto lógico) tendo como base o
modelo conceitual (DER), seguem os seguintes passos:

       Passo 1: para cada conjunto de entidades E no DER, crie uma rela-
       ção com o mesmo nome de E, e inclua todos os atributos simples
       de E. Para um atributo composto, inclua somente os componentes
       simples que compõem o atributo composto. Escolha como chave
       primária um dos atributos chave de E. Caso a chave seja composta,
       o conjunto de atributos simples formará a chave primária.

       Passo 2: para cada conjunto de entidades fraca F do DER que tem
       um conjunto de entidades proprietárias E, crie uma relação e inclua
       todos os atributos simples de F, e ainda, inclua somente os atribu-
       tos simples que compõem o atributo composto. Incluir como a
       chave estrangeira a chave primária da relação que corresponde ao



50                                                              Banco de dados
         conjunto de entidades proprietárias E. A chave primária é a com-
         binação da chave estrangeira com a chave parcial de F.

         Passo 3: para cada tipo de relacionamento binário 1:1, identifique
         as relações S e T que participam em R. Escolha uma das relações,
         por exemplo S, e inclua como chave estrangeira de S a chave pri-
         mária de T. Escolha o tipo de entidade com participação total em
         R como sendo a relação S. Inclua todos os atributos simples (ou
         os componentes simples de atributos compostos) do tipo de rela-
         cionamento 1:1, R, como atributo de S.

         Passo 4: para cada tipo de relacionamento 1:N entre S e T que par-
         ticipam de R, identifique a relação S que representa o lado N do
         tipo de relacionamento. Inclua como chave estrangeira em S a
         chave primária de T. Inclua como chave estrangeira em S a chave
         primária de T.

         Passo 5: para cada tipo de relacionamento M:N entre as relações
         S e T, crie uma relação R para representar o tipo de relacionamento
         M:N. Inclua como chave estrangeira em R as chaves primárias de
         S e T. Inclua também qualquer atributo simples do tipo relaciona-
         mento M:N (ou componente simples dos atributos compostos)
         como atributos de R.

         Passo 6: para cada atributo multivalorado A, crie uma nova rela-
         ção R. Inclua o atributo correspondente ao atributo multivalorado
         A em R. Inclua como chave estrangeira a chave primária K do tipo
         de entidade/relacionamento que possui A. Se o atributo for com-
         posto, deve-se atribuir seus componentes simples.

     Para o mapeamento do modelo entidade relacionamento estendido
para o relacional, deve-se repetir todos os passos do mapeamento do
modelo ER para o relacional (passos 1 a 7) vistos até o momento e, ainda,

          Passo 8: mapeamento de especialização ou generalização. Con-
          verta cada especialização com m subclasses {S1, S2, …, Sm} e super-
          classe generalizada C, em que os atributos de C são {k, a1, a2 … an}
          e k é a chave primária para os esquemas da relação usando as
          seguintes opções:

     • Opção 8A: múltiplas relações – superclasses e subclasses. Crie
          uma relação L para C com atributos Atr(L) = {k, a1, a2, …, an} e PK(L)
          = k. Crie uma relação Li para cada subclasse Si, 1 ≤ i ≤ m, com os
          atributos Atr(Li) = {k} ⋃ {atributos de Si} e PK(Li) = k.

     • Opção 8B: múltiplas relações – apenas relações de subclasses. Crie
          uma relação L, para cada subclasse Si, 1 ≤ i ≤ m, com os atributos
          Atr(Li) = {atributos de Si} ⋃ {k, a1, a2 … an} e PK(Li) = k. Ideal para espe-
          cializações cujas subclasses são disjuntas e totais (toda entidade
          em uma superclasse deve pertencer a, pelo menos, uma subclasse).

Considerações finais
     Este capítulo apresentou, inicialmente, o projeto lógico, que é uma
etapa do projeto de banco de dados em que se obtém um modelo lógico
a partir do modelo relacional.

     Na sequência, o texto introduziu o modelo relacional que é um modelo
lógico obtido a partir do mapeamento do DER. Para isso, definiu-se rela-
ção ou tabela, atributos e domínio de atributos, tuplas, superchaves, cha-
ves candidatas e chaves primárias.

     Além disso, mostrou as diversas restrições que podem ocorrer no
modelo relacional. Essas restrições são importantes para o projeto de
banco de dados, pois garantem a integridade e consistência do banco
de dados.

     Ao final, o texto descreve uma sequência de passos para realizar o
mapeamento do diagrama entidade relacionamento para o modelo
relacional.
