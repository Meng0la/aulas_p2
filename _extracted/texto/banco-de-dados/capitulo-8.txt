1 Organização do SGBD (Sistema de
Gerenciamento de Banco de Dados)
padrão SQL
      Em um banco de dados relacional, a estrutura lógica envolve tabelas,
índices e outros objetos, enquanto a estrutura física trata de como esses
objetos estão armazenados no disco e como são acessados, depen-
dendo do tipo de banco de dados.


1.1 Estrutura lógica

      A tabela é o principal objeto lógico de um banco de dados relacional.
Cada tabela é composta por linhas (também chamadas de registros ou
tuplas) e colunas (também chamadas de campos ou atributos). Uma
linha contém atributos de uma entidade. Por exemplo, uma linha da tabela
FUNCIONARIO representa uma entidade de funcionário, e o valor de cada
campo especifica um atributo que descreve um dado específico desse
funcionário (por exemplo, nome, CPF, endereço, supervisor) (Elmasri e
Navathe, 2018).

      Para auxiliar no desempenho da consulta, o banco de dados utiliza
índices que são estruturas de dados adicionais (como árvores B ou tabe-
las hash) para facilitar o acesso rápido aos dados. Cada índice contém
uma chave de pesquisa (geralmente uma coluna da tabela) e um apon-
tador para a localização física dos dados correspondentes.

      As visões e procedimentos armazenados são mecanismos lógicos
do banco de dados que não armazenam dados fisicamente, mas forne-
cem maneiras de acessar e manipular dados de forma eficiente.

1.2 Estrutura física

    A estrutura física de um banco de dados começa com o armazena-
mento em blocos de disco ou páginas. Um bloco é a unidade de trans-
ferência de dados entre disco e memória (Elmasri e Navathe, 2018). Cada
bloco possui um tamanho fixo e pode armazenar várias linhas da tabela.
Segundo Elmasri e Navathe (2018), há duas formas de organizar os blo-
cos de registros:

    • Organização espalhada aproveita o espaço em disco não permi-
         tindo a ocorrência de espaços vazio, mas permitindo a ocorrência
         do pedaço inicial de um registro num bloco, apontando para o
         pedaço final do registro em outro bloco.

    • Organização não espalhada, onde os registros não são espalhados
         em mais de um bloco, ou seja, cada bloco só possui registros com-
         pletos; assim, para ler um registro, basta ler apenas um bloco do
         disco.

    Sobre os arquivos do banco de dados são feitas as operações de recu-
peração (busca) e de modificação. São operações de modificação a inser-
ção e remoção de registros e a alteração de valores de campos de registros
do arquivo.

    Uma organização de arquivo refere-se à organização dos dados do
arquivo em registros, blocos e estruturas de acesso, distribuição e inter-
ligação na mídia de armazenamento. Um método de acesso diz respeito
à forma como o SGBD localiza, lê e escreve dados no meio de armaze-
namento físico. Eles influenciam diretamente no desempenho das con-
sultas e operações. Os principais métodos de acesso utilizados são:

    • Acesso sequencial ou pesquisa linear (do inglês, full table scan):
         varre todos os registros, passando bloco por bloco do arquivo, do
         início ao fim. Esse método é utilizado quando não há índice dispo-
         nível. Operações como COUNT(*), agregações ou varreduras com-

2 Catálogo de banco de dados
    O catálogo do banco de dados, também chamado de dicionário de
dados (em inglês data dictionary) é um conjunto de tabelas que armaze-
nam informações sobre o próprio banco de dados. Essa informação
armazenada no catálogo são “dados sobre outros dados”, isso é cha-
mado de metadados (Silberschatz, Korth e Sudarshan, 2020). O catálogo
contém a descrição do esquema conceitual do banco de dados, do
esquema interno, de todos os esquemas externos e dos mapeamentos
entre os esquemas. Além disso, nele também são armazenados os módu-
los de otimização de consultas, de segurança e de autorização.

    No caso dos bancos de dados relacionais, as informações devem ser
armazenadas no catálogo no formato relacional, isto é, em forma de

tabelas de catálogo, que são geradas no momento da criação do banco
de dados.

      Entre as informações armazenadas no catálogo, incluem-se:

      • Nomes das relações.

      • Nomes dos atributos de cada relação.

      • Domínio e tamanho do atributo.

      • Relacionamentos, chaves estrangeiras e referências entre as tabelas.

      • Estatísticas para otimização, tais como número de registro e tama-
         nho das tabelas.

      Descrições de visões e estruturas de armazenamento de índices tam-
bém podem ser armazenadas no catálogo; procedimentos armazena-
dos com informações sobre o nome do procedimento, parâmetros e
corpo do procedimento; informações de autorização e segurança tam-
bém; tudo na forma de relações, permitindo acesso generalizado ao catá-
logo via linguagem de consulta.

      Muitos bancos de dados relacionais armazenam seus arquivos de
catálogo como relações do SGBD. Mas, como há muito acesso ao catá-
logo, ele precisa ser implementado de forma eficiente.


3 Segurança e proteção de dados
      Segundo Ramakrishnan e Gerhke (2011), existem três objetivos prin-
cipais a serem considerados ao projetar uma aplicação de banco de
dados segura:

      1. Integridade: a integridade do banco de dados diz respeito à neces-
         sidade de proteger as informações contra alterações impróprias,
         ou seja, criar, excluir ou modificar valores. A perda da integridade



120                                                               Banco de dados
         pode ser intencional ou acidental e pode gerar fraudes ou tomada
         de decisão incorreta.

    2. Disponibilidade: usuários autorizados não devem ser impedidos
         de acessar o sistema. O funcionário que deseja alterar as suas
         informações pessoais, como por exemplo o número do celular que
         mudou, deve ter permissão para fazê-lo.

    3. Sigilo: as informações não devem estar disponíveis a usuários não
         autorizados. Por exemplo, um funcionário não deve ter permissão
         para visualizar as informações pessoais de outro funcionário.

    Para alcançar esses objetivos, é importante definir uma política de
segurança clara e consistente para descrever medidas de segurança que
precisam ser aplicadas (Ramakrishnan e Gehrke, 2011). No contexto do
sistema computacional, várias funções de segurança devem ser imple-
mentadas nas camadas de hardware, de sistema operacional e de SGBD.

    Num SGBD multiusuário são oferecidas técnicas para permitir acesso
a partes do BD ou para inibir o acesso a outras; desta forma, podem ser
administradas as informações confidenciais. Para isso, o SGBD é dotado
de um subsistema de autorização do BD contra acesso não autorizado,
que consiste em conceder ou revogar privilégios. Contudo, além de se
garantir a questão da confidencialidade deseja-se garantir a segurança
e a integridade da informação, garantindo prevenção contra o acesso de
pessoas não autorizadas na recuperação de informações e modificação
do conteúdo do banco de dados (Elmasri e Navathe, 2018).

    Uma solução bastante comum para o controle de acesso é o uso de
contas e senhas. Outra técnica que se pode aplicar é a criptografia dos
dados, comum quando há transmissão de dados por rede e quando se
quer proteger porções sensíveis do banco de dados (Elmasri e Navathe,
2018).

gerenciamento do banco de dados. Tem conta privilegiada: a conta de

      Uma pessoa ou grupo de pessoas é representada por uma conta cujo
acesso é liberado por meio de um login e de uma senha, com a criação
de uma tabela de login e senha e onde são definidas que operações se

do qual se conectou. A existência do log disponibiliza uma trilha de audi-
toria em que ser pode fazer exame de acessos e operações executadas
e, inclusive, verificar algum comportamento suspeito e possíveis viola-
ções de segurança.

      No contexto de um SGBD relacional, a administração de privilégios é
feita com o uso de instruções SQL, criadas para este propósito. Aqui,
usuários e contas são tratados como sinônimos. Existem dois níveis de
atribuição de privilégios, o nível de conta e o nível de relação. No nível de
conta são definidos os privilégios para criar, remover, alterar (modificar)
ou selecionar objetos como as tabelas ou as visões. Cada relação (real
ou virtual) tem um proprietário. No nível de relação são oferecidos os pri-
vilégios selecionar e modificar.

      Para realizar o controle de acesso discricionário o SQL fornece os
comandos GRANT (para concessão de privilégios) e o comando REVOKE
(para revogação de privilégios concedidos). Uma das primeiras conces-
sões é o direito de criação de tabelas do banco de dados. Normalmente,
este poder é concedido ao proprietário do banco de dados, que pode ser
definido no comando de criação do esquema do banco de dados. Como
exemplo, suponha o banco de dados Empresa, para dar permissão criar
tabela utilize o comando GRANT, como mostra o exemplo 2.

4 Serializações, atomicidades e transações
      Esta seção trata das transações, que são unidades atômicas de traba-
lho. Muitas aplicações de banco de dados requerem que as operações
envolvendo os dados sejam atômicas, ou seja, realizadas de forma indivi-
sível, mesmo que muitas operações concorrentes possam ocorrer simul-
taneamente. SQL oferece características e mecanismos que permitem
especificar transações e garantir que as operações sejam transações.

124                                                                                   Banco de dados
    Considere uma aplicação de transferência bancária entre contas.

    • Operação 1: Um valor é retirado da conta origem.

    • Operação 2: O mesmo valor é depositado na conta destino.

    Para o usuário, ambas as operações devem ocorrer com sucesso. Se
uma delas falhar, a transação toda deve ser desfeita, caso contrário, os
dados a tornarão inconsistente.

    Para o SGBD, uma transação é um programa em execução que forma
a unidade lógica de processamento de banco de dados (Elmasri e Nava-
the, 2018). Ela inclui operações de inserção, remoção, alteração ou
consulta.

    Em uma transação todas as operações devem ser concluídas com
sucesso, ou nenhuma operação deve ter efeito no banco, caso ocorra
alguma falha. Esse comportamento exige módulos específicos para
garantir a execução de forma completa e que seja possível executar
várias transações de maneira simultânea, sem gerar inconsistência dos
dados.

    As transações possuem várias propriedades, normalmente chama-
das de propriedades ACID (Elmasri e Navathe, 2018), são elas:

    • Atomicidade: uma transação é atômica quando deve ser realizada
         completamente ou não ser realizada de maneira alguma.

    • Consistência: uma transação deve preservar a consistência do
         banco de dados.

    • Isolamento: garante que as transações sejam executadas sem a
         interferência de outras.

    • Durabilidade ou permanência: garante que alterações ocorridas
         nas transações confirmadas serão mantidas no banco de dados.

      A serialização em banco de dados refere-se ao processo de garantir
que as transações sejam executadas de maneira segura e consistente,
evitando conflitos e garantindo a integridade dos dados. A ideia é que,
em um sistema com múltiplos usuários executando transações simul-
taneamente, as transações sejam executadas de modo que o estado
final do banco de dados seja equivalente a uma execução sequencial
dessas transações. Ou seja, a serialização garante que, ao final de todas
as transações, o banco de dados permaneça em um estado consistente,
como se cada transação fosse executada uma após a outra, em vez de
simultaneamente.

      Uma transação em SQL é uma coleção de uma ou mais operações
envolvendo banco de dados e deve se executada atomicamente, isto é,
todas as operações são completamente executadas ou nenhuma delas
é executada. Além disso, as transações devem ser executadas como se
sequencialmente, ou seja, elas são serializáveis.

      Segundo Elmasri e Navathe (2018), as transações iniciam quando
qualquer comando SQL que consulta ou manipula o banco de dados se
inicia. Não é necessário especificar qualquer comando inicial em SQL de
início de transação. Entretanto, deve-se finalizar uma transação explici-
tamente de uma das duas formas:

      • COMMIT: indica que todas as operações foram bem-sucedidas e
         podem ser gravadas no banco de dados.

      • ROLLBACK: indica que ocorreu uma falha e que todas as altera-
         ções feitas até então devem ser revertidas.

      Como exemplo, suponha a tabela CONTA que é criada no exemplo 8.

    Além dos comandos COMMIT e ROLLBACK, SQL possui um outro
comando, denominado SET TRANSACTION, que determina o compor-
tamento e a interação da transação com outras transações. Este
comando descreve as ações que os comandos de uma transação podem
executar, como uma transação deveria reagir a um conflito de trava-
mento de registro ou tabela e descreve a visão do banco de dados dada
a uma transação quando ela se relaciona com as ações por outras tran-
sações simultâneas.

    As ações que os comandos de uma transação podem executar são
definidas pelo modo de acesso da transação do banco de dados. O acesso
pode ser apenas para leitura (READ ONLY), usado quando as ações são
apenas de consulta às tabelas, ou para leitura e escrita (READ WRITE),

usado se o usuário deseja atualizar alguma tabela. Ambos os modos

      Um conflito de travamento pode ocorrer quando um registro ou uma
tabela requisitada por uma transação estiver sendo usado por uma outra
transação. SQL permite que o usuário decida se a transação que requi-
sitou o recurso deve esperar a sua liberação ou utilizar o recurso com o
estado antes da transação que o detém iniciar. O estado de espera é o
comportamento padrão, pode ser explicitamente modificado com a opção
NO WAIT present no comando SET TRANSACTION como mostra o exem-
plo 11.

                 Exemplo 11 – Comando SET TRANSACTION sem travamento


             SET TRANSACTION [READ ONLY|READ WRITE] NO WAIT;




Considerações finais
      Este capítulo apresentou aspectos lógicos e físicos da organização de
um banco de dados. Sobre os aspectos físicos, vimos como os arquivos
do banco de dados são organizados e as maneira como são acessados,
por meio de uma varredura sequencial ou acesso por índices. Após isso,

de dados, que contém um conjunto de tabelas com o registro de todos os

zenados, entre outros.
